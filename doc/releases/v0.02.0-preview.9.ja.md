# WindowResizer v0.02.0-preview.9

[English](v0.02.0-preview.9.md) | [한국어](v0.02.0-preview.9.ko.md) | [中文](v0.02.0-preview.9.zh-CN.md) | [日本語](v0.02.0-preview.9.ja.md)

リリース日: 2026-09-30

書き直した WPF（.NET 10）デスクトップアプリの 9 番目のプレビューです。`next/` 以下のソースから
ビルドし、配布される実行ファイルは引き続き PyQt5 アプリ v0.01.5 です。今回はオーバーレイボタンの
プロパティ画面に実寸プレビューを追加しました。

## 主な変更

- ボタンのプロパティ画面の外観ページで、ボタンを画面に出る実際の大きさでプレビューします。実際のボタンと
  同じコードで描画し、設定ページのアプリ倍率の影響を受けない（Windows の倍率だけに従う）ので、150 x 46 は
  150 x 46 に見えます。
- 名前、文字、形、サイズ、色を変えている間、画面に浮かんでいる実際のボタンも保存前に同じように変わります。
  キャンセルすると元に戻ります。保存を押すまでは何も書き込みません。
- 幅と高さの欄は入力に合わせてすぐ反映されます。

## このプレビューにまだ無いもの

- 画面上での直接編集（ドラッグ、サイズ変更ハンドル、編集モード）は未実装です。
- プレビューは待機ゲージとマウスを載せたときの色を表示しません。
- プレビューの背景はウィンドウの背景のままです（明暗の切り替えはありません）。

## 互換性

- プロファイルと設定の形式は変わりません。新しいコマンドラインオプションはありません。

## 検証

- .NET ソリューションのビルド: 警告 0 件、エラー 0 件。
- .NET テスト: 245 件（Core 105、App 103、Infrastructure 37。フォーカスに依存するライブテスト 1 件は
  スキップ）、失敗なし。レンダリングスモークがアプリ倍率 200% でプレビューを描画して 150 x 46 のままで
  幅の変更に追従することを確認し、他のテストがプレビューの値（範囲外のサイズは保存時と同じく補正、名前が
  空なら元の名前）と、ウィンドウを閉じたとき設定を書かずに実際のボタンからプレビューを外すことを確認します。
- 実際のプロファイルのコピー、一時的なレジストリキー、使い捨てウィンドウを使い、UI Automation で
  確認しました: プロパティ画面で幅を 300 にすると実際のボタンウィンドウが 241 から 481 物理ピクセルに広がり
  （この PC は 160% 倍率）、キャンセルすると 241 に戻りました。実際の `profiles.json` とコピーは変わって
  いません。
