# WindowResizer v0.02.0-preview.3

[English](v0.02.0-preview.3.md) | [한국어](v0.02.0-preview.3.ko.md) | [中文](v0.02.0-preview.3.zh-CN.md) | [日本語](v0.02.0-preview.3.ja.md)

릴리스 날짜: 2026-09-29

새로 작성한 WPF(.NET 10) 데스크톱 앱의 세 번째 미리보기입니다. 앞선 미리보기와 같이
`next/` 아래 소스에서 빌드하며 패키지로 배포하지 않습니다. 배포 실행 파일은 계속
PyQt5 앱 v0.01.5 입니다.

## 주요 변경

- 단축키 페이지. 전체 적용 단축키 하나가 모든 프로필을 맞는 창 전부에 적용합니다(새
  프로필 > 전체 프로필 적용 메뉴와 같은 경로). 프로필마다 단축키를 최대 3개까지 두고,
  각각 동작을 고릅니다: 프로필 적용, 잠금 해제, 항상 위 전환, 자동 적용 전환. 프로필별
  스위치로 그 프로필의 단축키를 한꺼번에 켜고 끕니다.
- 단축키는 한 줄에서 고릅니다: 수정키 칩 4개(Ctrl, Alt, Shift, Win), 키 목록, 감지 버튼.
  감지를 누르고 단축키를 그대로 누르면 한꺼번에 채워지고, 손으로 골라도 됩니다. 최대 5개까지
  됩니다(수정키 4개 + 키 1개: Windows 는 수정키가 아닌 키를 하나만 받습니다). 감지 중과
  프로필 편집 창이 열려 있는 동안에는 전역 등록을 풀어, 이미 등록된 단축키를 눌러도 동작이
  실행되지 않고 줄이 채워집니다. 다른 프로그램이 이미 쥔 조합은 누르는 키를 그 프로그램이
  가져가 감지되지 않으니 손으로 고르세요. 줄마다 저장 버튼이 있고, 저장하지 않은 변경은 그렇게
  알립니다. 프로필 편집 창도 같은 줄을 씁니다.
- 줄은 바뀌는 즉시 검사합니다. 형식이 틀렸거나, 다른 줄과 겹치거나, 다른 프로그램이나
  Windows 가 쓰는 조합(예: Win+L)이면 이유와 함께 빨간 테두리가 붙습니다. 그런 조합도 v0.01.5
  처럼 저장은 하고, 왜 동작하지 않는지 경고 상자로 알립니다.
- 페이지가 모든 단축키를 등록 결과와 함께 보여 줍니다. 다른 프로그램이 이미 쓰는 조합,
  형식이 틀린 조합, 알 수 없는 동작, 중복은 조용히 실패하지 않고 이유가 보이며, 나머지는
  계속 등록됩니다. 프로필을 저장하거나 지울 때마다 다시 등록하고, 단축키와 무관한 저장
  (적용 횟수 등)은 등록을 건드리지 않습니다.
- 전체 적용 단축키는 `HKCU\Software\WindowResizer\Next\Hotkeys` 에 저장합니다. 처음 한
  번 v0.01.5 의 `application_hotkeys.json` 값을 가져오고(시험 PC 에서는 Ctrl+Alt+E),
  그 파일에는 쓰지 않습니다. v0.01.5 와 같이 Windows 가 등록을 거절해도 단축키는 저장하고
  페이지가 그렇게 알립니다.
- 프로필 편집 창은 프로필에 단축키 세트가 있으면 단일 단축키 칸을 닫고 단축키 페이지를
  안내합니다. 거기서 고쳐도 아무 일도 안 일어나는 일이 없어집니다. 프로필 목록의 단축키
  열은 등록되는 첫 단축키를 보여 줍니다.

## 이 미리보기에 아직 없는 것

- 잠금 해제는 풀 것이 없습니다. 이 미리보기는 아직 창을 잠그거나 마우스를 가두지 않으므로
  단축키는 상태 줄에 그렇게 알리기만 합니다.
- 자동 적용 전환은 프로필의 설정을 뒤집어 저장합니다. 새 창을 감지해 자동으로 적용하는
  기능은 이 미리보기에 없습니다.
- 항상 위 전환은 v0.01.5 와 같이 프로필이 아니라 앞에 있는 창에 작용합니다.
- 설정 페이지(테마, UI 크기, 언어), 로그와 정보 페이지, 앱 아이콘, 패키지 실행 파일.

## 호환성

- 프로필은 `hotkey_sets` 를 포함해 같은 `profiles.json` 형식입니다. 저장하면 PyQt5 편집
  창처럼 첫 세트를 `hotkey_combination`, `hotkey_action` 에도 적습니다. 미리보기는 넘겨받은
  프로필 폴더(`--profiles-dir`)에 쓰므로 사본으로 시험하세요. `--hotkey-key` 는 시험용으로
  전체 적용 단축키를 다른 레지스트리 키에 둡니다.

## 검증

- .NET 솔루션 빌드: 경고 0개, 오류 0개.
- .NET 테스트: 159개, 모두 통과했습니다(Core 68, App 61, Infrastructure 30). 등록 계층에
  실제 키 입력을 보내는 테스트를 포함합니다.
- 프로필 사본으로 실행 중인 앱에서 실제 키 입력으로: 전체 적용 단축키 Ctrl+Alt+E 가 일회용
  창을 프로필 위치로 옮겼고, 프로필 단축키가 프로필을 적용했으며, 항상 위 전환이 앞에 있는
  창을 켜고 껐고, 자동 적용 전환이 설정을 양쪽으로 뒤집어 저장했습니다. 다른 프로그램이 쥔
  조합은 충돌 이유와 함께 목록에 보였고 나머지는 등록된 채였습니다. 이미 등록된 Ctrl+Alt+E 를 감지하면 창이 움직이지 않고 줄이 채워졌고, 새
  조합을 감지하면 칩과 키가 한꺼번에 채워졌으며, 칩을 켜고 키를 손으로 고르는 것도 됐습니다.
  다른 프로그램이 쥔 조합은 이유와 함께 줄이 빨개졌고, 저장하면 값은 저장되고 경고 상자가
  떴으며, 비어 있는 조합으로 바꿔 저장하면 경고 없이 새 단축키가 전체 적용을 실행했습니다.
  실제 프로필 파일은 바뀌지 않았습니다.
