# WindowResizer v0.02.0-preview.2

[English](v0.02.0-preview.2.md) | [한국어](v0.02.0-preview.2.ko.md) | [中文](v0.02.0-preview.2.zh-CN.md) | [日本語](v0.02.0-preview.2.ja.md)

リリース日: 2026-09-29

書き直した WPF（.NET 10）デスクトップアプリの 2 番目のプレビューです。preview.1 と同じく
`next/` 以下のソースからビルドし、パッケージとしては配布しません。配布される実行ファイルは
引き続き PyQt5 アプリ v0.01.5 です。

## 主な変更

- オーバーレイボタンが画面に表示されます。オーバーレイボタンをオンにしたプロファイルごとに
  フローティングボタンが 1 つ出て、直前に使っていたウィンドウにそのプロファイルを適用します。
  クリックするか、マウスをドウェル時間（0.2〜5.0 秒）のあいだ載せてゲージが満ちるのを
  待ちます。ドラッグで移動、位置のロック、右クリックで閉じる、結果は緑または赤の点滅で
  表示します。保存された位置は接続中のモニター内にあるときだけ使います。v0.01.5 と同じく、
  プロファイルの一致条件が選ばないウィンドウでも、ボタンは直前に前面にあったウィンドウに
  適用します。
- ボタンはフォーカスを奪いません。このプレビューで修正しました: 以前はボタンを押すと
  WindowResizer 自身のウィンドウが前面に出て、「直前のウィンドウ」が WindowResizer 自身に
  なり得ました。ウィンドウスタイルとクリックによるアクティブ化の遮断を併用し、フォーカスは
  使っていたウィンドウに残ります。
- 非表示スイッチ: 小さな目のボタンで、オーバーレイボタンをまとめて隠したり表示したりします。
  置いた位置を覚え、自分自身は隠れず、スイッチを外すと隠れていたボタンが再び表示されます。
  数ピクセルだけ動かしたものはクリックとして数えません。
- 初回起動時に v0.01.5 のオーバーレイ設定（発動方法、ドウェル時間、非表示、スイッチ、
  ロック）を取り込みます。そちらでボタンを隠していた場合、こちらも隠れた状態で始まり、
  戻す手段がスイッチです。ボタンの位置は新しく始まります。

## このプレビューにまだないもの

- ショートカットページ、設定ページ（テーマ、UI サイズ、言語）、ログと情報ページ。
- アプリアイコンとパッケージ化された実行ファイル。

## 互換性

- プロファイルは同じ `profiles.json` 形式です。オーバーレイ設定は
  `HKCU\Software\WindowResizer\Next\Overlay` に物理ピクセルで保存します。プレビューは渡された
  プロファイルフォルダー（`--profiles-dir`）に書き込むため、コピーで試してください。

## 検証

- .NET ソリューションのビルド: 警告 0 件、エラー 0 件。
- .NET テスト: 112 件、連続 3 回の再実行ですべて合格しました。1 回の全体実行では、ウィンドウを
  前面に出す必要があるライブテストが、Windows によるフォーカス移動の遮断のため判定不能として
  スキップされました。
- 実行中のアプリで実際のマウスクリックにより: オーバーレイボタンを押しても対象ウィンドウは
  前面に残り、プロファイルの位置に正確に移動し、適用回数が保存されました。非表示スイッチは
  フォーカスを奪わずにボタンを隠して再表示し、ドラッグするとドラッグした距離ぴったり移動して
  新しい位置が保存され、切り替えは起きませんでした。
