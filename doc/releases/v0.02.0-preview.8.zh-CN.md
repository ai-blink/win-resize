# WindowResizer v0.02.0-preview.8

[English](v0.02.0-preview.8.md) | [한국어](v0.02.0-preview.8.ko.md) | [中文](v0.02.0-preview.8.zh-CN.md) | [日本語](v0.02.0-preview.8.ja.md)

发布日期：2026-09-30

重写的 WPF（.NET 10）桌面应用的第八个预览版，从 `next/` 下的源码构建；分发的可执行文件仍是
PyQt5 应用 v0.01.5。本预览让悬浮按钮独立于配置文件，并为 4K 屏幕扩大了界面缩放范围。

## 主要变更

- 悬浮按钮拥有自己的位置。按钮现在独立于配置文件，保存自己的名称以及要恢复的窗口位置和大小（X、Y、
  宽、高、最大化）。按下后，会把刚才使用的窗口移到该位置。配置文件匹配、快捷键和自动应用都不参与。
- 右键菜单：按钮名称（粗体）、已保存的位置、“属性...”、“用当前窗口的位置覆盖”、“复制”和“删除此按钮”
  （会先询问）。
- 按钮属性窗口（与配置文件编辑窗口相同的左侧导航）：常规（名称、按钮上显示的文字）、大小和位置（X、Y、
  宽、高、最大化、“从上一个窗口获取”）、行为（触发方式和停留时间）、外观（形状、大小、颜色）。
- 悬浮按钮页面列出按钮（属性、删除），“新建按钮”会用刚才使用的窗口的位置和大小创建按钮。
- 首次启动时，曾开启悬浮按钮的配置文件会一次性复制为按钮（名称、位置和大小、外观、按钮的屏幕位置）。
  配置文件不会改变，以后也不会再次复制，因此删除的按钮不会复活。
- “全部关闭”改为“隐藏所有按钮”：只隐藏按钮（与隐藏开关相同），不删除任何按钮。
- 界面缩放范围改为 75% 到 250%（原为 75% 到 125%）。这台电脑上已保存的值不会改变，请在设置页面调高。

## 本预览尚未包含

- 直接在屏幕上编辑（拖动移动、用手柄调整大小、编辑模式）尚未完成。位置和大小用数字和“从上一个窗口
  获取”修改。
- “用当前窗口的位置覆盖”没有撤销；状态栏会显示旧位置和新位置。
- 配置文件编辑窗口仍有“使用悬浮按钮”，配置文件也仍带有悬浮样式。它们不再创建按钮，提示文字已说明。
  移除它们是后续步骤。
- 未能验证对运行中按钮的真实鼠标右键（见下）。
- Windows 100/125/150/200% 缩放检查仍未验证，250% 也没有用眼睛检查。

## 兼容性

- 配置文件格式没有变化。悬浮设置（`HKCU\Software\WindowResizer\Next\Overlay`）新增 `buttons` 和
  `buttons_migrated` 值，旧版本会忽略。复制而来的按钮的屏幕位置仍以旧配置文件 ID 保存，因此位置得以延续。

## 验证

- .NET 解决方案构建：0 个警告，0 个错误。
- .NET 测试：243 个，全部通过（Core 105、App 101、Infrastructure 37）。新测试覆盖按钮模型及保存值、
  仅复制一次配置文件、用按钮移动窗口、从窗口创建和覆盖、名称重复与复制、属性视图模型，以及打开菜单并点击
  各项、绘制属性窗口四个页面的渲染冒烟测试。
- 使用真实配置文件的副本、临时注册表键和一次性窗口，通过 UI Automation 验证：开启悬浮按钮的 3 个配置文件
  变成了 3 个按钮，“新建按钮”用一次性窗口创建并保存了第 4 个按钮，属性窗口以该按钮的名称打开。真实的
  `profiles.json` 和副本均未改变。
- 未能验证：对运行中按钮的真实鼠标右键。电脑正在使用，光标一直在移动，菜单改由渲染冒烟测试验证。
