# WindowResizer v0.02.0-preview.8

[English](v0.02.0-preview.8.md) | [한국어](v0.02.0-preview.8.ko.md) | [中文](v0.02.0-preview.8.zh-CN.md) | [日本語](v0.02.0-preview.8.ja.md)

Release date: 2026-09-30

Eighth preview of the rewritten WPF (.NET 10) desktop app, built from source under `next/`;
the distributed executable is still the PyQt5 app, v0.01.5. This preview makes overlay buttons
independent of profiles and raises the UI scale range for 4K screens.

## Highlights

- Overlay buttons keep their own place. A button now stores its own name and the window place
  and size it restores (X, Y, width, height, maximized), apart from any profile. Pressing it moves
  the window you were just using to that place. Profile matching, hotkeys and auto-apply are not
  involved.
- Right-click menu: the button name (bold), its saved place, "Properties...", "Overwrite with the
  current window's place", "Duplicate" and "Delete this button" (asks first).
- Button properties window (left rail, like the profile editor): General (name, text on the button),
  Size and place (X, Y, width, height, maximized, "Take from the last window"), Behavior (activation
  and rest time) and Look (shape, size, colours).
- The Overlay page lists the buttons with Properties and Delete, and "New button" makes a button
  from the place and size of the window you were just using.
- On the first start, profiles that had an overlay button are copied into buttons once (name, place
  and size, look, and the button's screen position). The profiles are not changed and nothing is
  copied again later, so a button you delete stays deleted.
- "Hide all buttons" replaces "Close all": it hides the buttons (same as the hide switch) and deletes
  none.
- UI scale range is now 75% to 250% (was 75% to 125%). The setting already saved on a PC is not
  changed; raise it on the Settings page.

## Not yet in this preview

- Editing on the screen itself (dragging to move and resize a button with handles, an edit mode) is
  not done. Place and size are edited with numbers and "Take from the last window".
- Undo for "Overwrite with the current window's place" is not done; the status line shows the old and
  new place.
- The profile editor still shows "Use an overlay button" and the profile carries an overlay style.
  They no longer create buttons; the hint says so. Removing them is a later step.
- A real mouse right-click on a running button was not verified (see below).
- The Windows 100/125/150/200% scaling smoke is still not verified; 250% was not looked at by eye.

## Compatibility

- Profile format unchanged. The overlay settings gain `buttons` and `buttons_migrated` values in
  `HKCU\Software\WindowResizer\Next\Overlay`; older builds ignore them. Button positions stay keyed
  by the old profile id for copied buttons, so the places carry over.

## Verification

- .NET solution build: 0 warnings, 0 errors.
- .NET tests: 243 tests, all passed (Core 105, App 101, Infrastructure 37). New tests cover the button
  model and its saved values, copying profiles once, applying a button to a window, creating and
  overwriting from a window, unique names and duplicates, the properties view model, and a render
  smoke that opens the menu, clicks each item and draws all four properties pages.
- Live, on a copy of the real profiles with temporary registry keys and a disposable window, driven
  by UI Automation: the three overlay profiles became three buttons, "New button" made a fourth
  from the disposable window and saved it, and the properties window opened with that button's name.
  The real `profiles.json` and the copy were not changed.
- Not verified: a real mouse right-click on a running button. The PC was in use and the cursor kept
  moving; the render smoke covers the menu instead.
