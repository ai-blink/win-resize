# WindowResizer v0.02.0-preview.3

[English](v0.02.0-preview.3.md) | [한국어](v0.02.0-preview.3.ko.md) | [中文](v0.02.0-preview.3.zh-CN.md) | [日本語](v0.02.0-preview.3.ja.md)

Release date: 2026-09-29

Third preview of the rewritten WPF (.NET 10) desktop app. Like the earlier previews
it is built from source under `next/` and is not a packaged release; the
distributed executable is still the PyQt5 app, v0.01.5.

## Highlights

- Shortcuts page. One global apply-all shortcut applies every profile to all its
  matching windows (the same path as the new Profile > Apply all profiles menu
  item). Each profile can have up to three shortcuts, each with its own action:
  apply the profile, release locks, toggle always on top, toggle auto apply. A
  switch per profile turns all of its shortcuts on or off.
- The page lists every shortcut with its result. A combination another program
  already holds, an invalid combination, an unknown action and a duplicate are
  shown with the reason instead of failing silently, and the others still register.
  Shortcuts are registered again whenever a profile is saved or deleted; saves that
  do not touch shortcuts (such as the applied count) leave them alone.
- The apply-all shortcut is stored in `HKCU\Software\WindowResizer\Next\Hotkeys`. The
  first time, the value in the v0.01.5 file `application_hotkeys.json` is imported
  (on the test PC that is Ctrl+Alt+E); that file is never written. As in v0.01.5 the
  shortcut is saved even when Windows refuses to register it, and the page says so.
- The profile editor closes its single-shortcut box when a profile has shortcut
  sets and points to the Shortcuts page, so an edit there can no longer do nothing.
  The profile list's Shortcut column shows the first registered shortcut.

## Not yet in this preview

- Release locks has nothing to release: this preview does not lock windows or
  confine the mouse yet, so the shortcut only says so in the status line.
- Toggle auto apply flips and saves the profile's setting; detecting new windows
  and applying automatically is not in this preview.
- Toggle always on top acts on the window in front, not on a profile, as in v0.01.5.
- Settings page (theme, UI scale, language), log and about page, app icon and a
  packaged executable.

## Compatibility

- Profiles use the same `profiles.json` format, including `hotkey_sets`; saving
  keeps the first set in `hotkey_combination` and `hotkey_action` too, as the
  PyQt5 editor does. The preview writes to the profile folder it is given
  (`--profiles-dir`): test against a copy. `--hotkey-key` points the apply-all
  shortcut at another registry key for testing.

## Verification

- .NET solution build: 0 warnings, 0 errors.
- .NET tests: 144 tests, all passed (Core 66, App 49, Infrastructure 29), including
  real key input sent to the registration layer.
- On the running app against a copy of the profiles, with real key presses: the
  apply-all shortcut Ctrl+Alt+E moved a disposable window onto the profile's
  position; a profile shortcut applied the profile; toggle always on top switched
  the window in front on and off; toggle auto apply flipped and saved the setting
  both ways. A combination held by another program was listed with the conflict
  reason while the others stayed registered. The real profile file was unchanged.
