# WindowResizer v0.02.0

[English](v0.02.0.md) | [한국어](v0.02.0.ko.md) | [中文](v0.02.0.zh-CN.md) | [日本語](v0.02.0.ja.md)

Release date: 2026-09-30

The first stable release of the rewritten WindowResizer. It replaces the PyQt5 app (v0.01.5) as the
distributed executable: the app is now WPF on .NET 10, shipped as one self-contained
`WindowResizer.exe` (about 72 MB) that carries its own .NET runtime.

SHA-256 of `WindowResizer.exe`: `9323D2A52C49C7A96FBD92E64FB6F57EEDDA001ED5E84A698DCC29843497F373`

## Highlights

- A sidebar app with five pages: Windows and profiles, Overlay buttons, Shortcuts, Settings, Log and About.
- Profiles: save a window's place (Ctrl+S), apply to every matching window, overwrite a place from a window
  with undo, match by executable path, process name, title (contains, exact, regex) or a combination.
  Existing v0.01.5 `profiles.json` files are read and written in the same format; keys the app does not
  know are kept.
- Position lock: a profile's window that is dragged or resized away is put back to the place it was applied
  at (tolerance, restore on move, restore on resize and the max attempts of the profile are honoured).
  Maximized and minimized windows are left alone. A window that cannot be moved (for example an
  administrator window) is given up after the profile's max attempts and the status line says so.
- Mouse confinement: the cursor is confined to the profile's window only while that window is in front; it
  is released when you switch away and confined again when you come back. The profile's escape key
  (default Escape) frees it until the profile is applied again.
- New-window auto-apply: a window that appears after the app starts and matches an auto-apply profile gets
  the profile automatically, using that profile's `apply_delay`, `max_retries` and `retry_delay`. When
  several profiles match, the most specific one wins. Windows already open at start are not touched.
  The status bar shows "Watching for new windows: N profile(s)".
- Overlay buttons: each button stores its own name and the window place and size it restores, apart from
  profiles, and moves the window you were just using there. A properties window (General, Size and
  place, Behavior, Look) has an actual-size preview; a place can be taken from the last window or picked on
  screen with an outline like a capture tool. Profiles that had an overlay in v0.01.5 are copied into
  buttons once on the first start.
- Global shortcuts per profile (several combinations and actions), an apply-all shortcut and an
  always-on-top toggle; a combination another program holds is listed with the reason.
- Settings: light, dark or follow-system theme (Windows high contrast is honoured), an app scale of 75% to
  250%, Korean or English labels, start with Windows, remember the window place.
- A log page keeps every status message and unhandled error and can be copied or exported.
- Single instance: only one copy runs per Windows session (the same mutex as v0.01.5, so the two apps do
  not run together); a second start brings the first window forward instead of doing nothing.
- The app stays in the system tray when its window is closed; Ctrl+Q or the tray menu exits.

## Changes from v0.01.5 you may notice

- The mouse is no longer kept inside the window after you switch to another window (v0.01.5 kept it until
  the release shortcut).
- The escape key of a profile now works (v0.01.5 saved it but ignored it).
- A lock restores to the window's real place after the move, not to the value in the profile, so a window
  with a minimum size does not fight the lock forever.
- New-window auto-apply follows each profile's delay and retry settings (v0.01.5 used fixed values) and
  needs no separate start button: it runs while at least one enabled profile has auto-apply on.
- Overlay buttons are separate from profiles (see above), and "Close all" became "Hide all buttons".

## Not in this release

- The three-second profile preview outline of v0.01.5.
- Chinese and Japanese labels inside the app (Korean and English only; documents are in four languages).
- An installer and an update mechanism.
- The on-screen edit mode for overlay buttons (drag and resize handles) and undo of "Overwrite with the
  current window's place".
- The profile editor still shows "Use an overlay button"; it no longer creates buttons.

## Compatibility

- Profile files keep the v0.01.5 format. Settings live in `HKCU\Software\WindowResizer\Next`; the theme,
  app scale and overlay settings of v0.01.5 are read once on the first start and never written back.
- Windows 10 or 11, 64-bit. Windows that run as administrator cannot be controlled by a standard-privilege
  WindowResizer; run it at the same level when needed.

- Checked on a copy of the profiles with temporary registry keys, driven by UI Automation: the overlay
  buttons (copy from profiles, New button, properties window, actual-size preview, the on-screen picker
  outline and Esc), a second start signalling the first, and that the real `profiles.json` was not changed.
- Not checked by a real mouse click: the overlay button right-click menu and choosing a window with the
  on-screen picker. The lock, the mouse confinement and the auto-apply monitor were tested with fakes and
  their wiring, not against real programs in this release process; please report anything odd.
