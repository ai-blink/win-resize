# WindowResizer v0.02.0-preview.8

[English](v0.02.0-preview.8.md) | [한국어](v0.02.0-preview.8.ko.md) | [中文](v0.02.0-preview.8.zh-CN.md) | [日本語](v0.02.0-preview.8.ja.md)

リリース日: 2026-09-30

書き直した WPF（.NET 10）デスクトップアプリの 8 番目のプレビューです。`next/` 以下のソースから
ビルドし、配布される実行ファイルは引き続き PyQt5 アプリ v0.01.5 です。今回はオーバーレイボタンを
プロファイルから独立させ、4K 画面向けに画面倍率の範囲を広げました。

## 主な変更

- オーバーレイボタンが自分の位置を持ちます。ボタンはプロファイルとは別に、自分の名前と復元するウィンドウの
  位置・サイズ（X、Y、幅、高さ、最大化）を保存します。押すと、直前に使っていたウィンドウをその位置に
  移動します。プロファイルの一致条件、ホットキー、自動適用は関与しません。
- 右クリックメニュー: ボタン名（太字）、保存された位置、「プロパティ...」、「現在のウィンドウの位置で
  上書き」、「複製」、「このボタンを削除」（先に確認します）。
- ボタンのプロパティ画面（プロファイル編集画面と同じ左レール）: 全般（名前、ボタンに表示する文字）、
  サイズと位置（X、Y、幅、高さ、最大化、「直前のウィンドウから取得」）、動作（発動方式と待機時間）、
  外観（形、サイズ、色）。
- オーバーレイページにボタンの一覧（プロパティ、削除）があり、「新しいボタン」は直前に使っていた
  ウィンドウの位置とサイズでボタンを作ります。
- 初回起動時に、オーバーレイを有効にしていたプロファイルを一度だけボタンにコピーします（名前、位置と
  サイズ、見た目、ボタンの画面上の位置）。プロファイルは変わらず、以後は再コピーしないので、削除した
  ボタンは復活しません。
- 「すべて閉じる」は「すべてのボタンを隠す」になりました。ボタンを隠すだけ（隠しスイッチと同じ）で、
  削除はしません。
- 画面倍率の範囲は 75%〜250% になりました（以前は 75%〜125%）。この PC にすでに保存されている値は
  変わらないので、設定ページで上げてください。

## このプレビューにまだ無いもの

- 画面上での直接編集（ドラッグで移動、ハンドルでサイズ変更、編集モード）は未実装です。位置とサイズは数値と
  「直前のウィンドウから取得」で編集します。
- 「現在のウィンドウの位置で上書き」の元に戻す機能はありません。ステータスバーに以前の位置と新しい位置が
  表示されます。
- プロファイル編集画面には「オーバーレイボタンを使う」が残り、プロファイルもオーバーレイの見た目を持って
  います。ボタンは作らなくなり、説明文にもそう書きました。削除は次の段階です。
- 実行中のボタンへの実際のマウス右クリックは検証できませんでした（下記）。
- Windows の 100/125/150/200% スケーリング確認は未検証のままで、250% は目で確認していません。

## 互換性

- プロファイルの形式は変わりません。オーバーレイ設定（`HKCU\Software\WindowResizer\Next\Overlay`）に
  `buttons` と `buttons_migrated` の値が増えます。古いビルドは無視します。コピーされたボタンの画面位置は
  元のプロファイル ID のまま保存されているので、位置は引き継がれます。

## 検証

- .NET ソリューションのビルド: 警告 0 件、エラー 0 件。
- .NET テスト: 243 件、すべて成功（Core 105、App 101、Infrastructure 37）。新しいテストは、ボタンモデルと
  保存値、プロファイルを一度だけコピー、ボタンでウィンドウを移動、ウィンドウから作成と上書き、名前の重複と
  複製、プロパティのビューモデル、メニューを開いて各項目を押しプロパティ画面の 4 ページを描画する
  レンダリングスモークを対象にします。
- 実際のプロファイルのコピー、一時的なレジストリキー、使い捨てウィンドウを使い、UI Automation で確認
  しました: オーバーレイを有効にしていた 3 つのプロファイルが 3 つのボタンになり、「新しいボタン」が
  使い捨てウィンドウから 4 つ目のボタンを作って保存し、プロパティ画面がそのボタンの名前で開きました。
  実際の `profiles.json` とコピーは変わっていません。
- 検証できなかったこと: 実行中のボタンへの実際のマウス右クリック。PC を使用中でカーソルが動き続けたため、
  メニューはレンダリングスモークで代わりに確認しました。
