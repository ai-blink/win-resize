# WindowResizer v0.02.0-preview.2

[English](v0.02.0-preview.2.md) | [한국어](v0.02.0-preview.2.ko.md) | [中文](v0.02.0-preview.2.zh-CN.md) | [日本語](v0.02.0-preview.2.ja.md)

Release date: 2026-09-29

Second preview of the rewritten WPF (.NET 10) desktop app. Like preview.1 it is
built from source under `next/` and is not a packaged release; the distributed
executable is still the PyQt5 app, v0.01.5.

## Highlights

- Overlay buttons are on screen now. Each profile whose overlay button is on gets
  a floating button that applies the profile to the window you were just using:
  click it, or rest the mouse on it for the dwell time (0.2-5.0 s) and watch the
  gauge fill. Drag to move, lock the positions, right-click to close, and a green
  or red flash shows the result. Saved positions are used only while they are still
  on a connected monitor. As in v0.01.5, a button applies its profile to the last
  window in front even when the profile's matching would not pick it.
- Buttons never take focus. Fixed in this preview: clicking a button used to raise
  WindowResizer's own window, so "the last window" would have been WindowResizer
  itself. The window style plus a click-activation guard now keep focus on your
  window.
- Hide switch: a small eye button hides and shows all overlay buttons at once. It
  remembers where you put it, never hides itself, and removing it shows any hidden
  buttons again. Dragging it a few pixels never counts as a click.
- Overlay settings from v0.01.5 carry over the first time (mode, dwell time, hide,
  switch, lock). If the buttons were hidden there, they start hidden here and the
  switch is the way back. Button positions start fresh.

## Not yet in this preview

- Hotkeys page, settings page (theme, UI scale, language), log and about page.
- App icon and a packaged executable.

## Compatibility

- Profiles use the same `profiles.json` format. Overlay settings are stored in
  `HKCU\Software\WindowResizer\Next\Overlay`, in physical pixels. The preview
  writes to the profile folder it is given (`--profiles-dir`): test against a copy.

## Verification

- .NET solution build: 0 warnings, 0 errors.
- .NET tests: 112, all passed in three consecutive reruns. In one full run a live
  test that needs a window in the foreground was skipped as inconclusive because
  Windows blocked the focus change.
- On the running app with real mouse clicks: clicking an overlay button kept the
  target window in front, moved it exactly onto the profile's position and saved
  the applied count. The hide switch hid and re-showed the buttons without taking
  focus; dragging it moved it by exactly the drag distance, saved the new position
  and did not toggle.
