# WindowResizer v0.02.0-preview.4

[English](v0.02.0-preview.4.md) | [한국어](v0.02.0-preview.4.ko.md) | [中文](v0.02.0-preview.4.zh-CN.md) | [日本語](v0.02.0-preview.4.ja.md)

发布日期：2026-09-30

重写的 WPF（.NET 10）桌面应用的第四个预览版。与之前的预览版一样，它从 `next/` 下的源码构建，
不是打包发布版；对外分发的可执行文件仍是 PyQt5 应用 v0.01.5。

## 主要变化

- 设置页面。主题（浅色、深色、跟随系统）、显示大小、语言、随 Windows 启动，以及记住窗口大小和位置。
  每项更改都会立即保存并生效，无需重启。
- 主题。“跟随系统”会在应用运行期间跟随 Windows 应用模式。开启 Windows 高对比度时，无论选择了什么，
  始终使用其颜色。
- 显示大小为 75% 到 125%，以 5% 为步长（默认 100%）。文字、间距和控件一起放大，窗口也随之变大。
  拖动滑块时只有旁边的数字会变化，松开后才应用大小。曾试过在拖动中应用并实测：滑块本身会随大小放大缩小，从光标下移开，数值在两个档位之间来回跳动。按键和点击滑轨
  会立即应用。重置按钮回到 100%。
- 语言为韩语或英语，无需重新打开窗口即可切换，涵盖界面、菜单、托盘菜单和快捷键列表。
- 随 Windows 启动会为当前用户添加启动项（无需管理员权限），启动时只显示在托盘中而不打开窗口
  （`--minimized`）。复选框显示的是 Windows 中实际注册的状态，而不是自己的副本。
- 记住窗口大小和位置。主窗口会在上次的位置重新打开；如果位置在所有显示器之外（拔掉了显示器或分辨率
  改变），会被移回屏幕内，窗口也不会小于最小尺寸。
- 首次运行时会从 v0.01.5 的设置导入主题和显示大小（测试电脑上为：跟随系统、75%），并单独保存在
  `HKCU\Software\WindowResizer\Next\Settings`；不会写入 v0.01.5 的键。v0.01.5 的窗口大小和位置不会导入：
  它们是 Qt 逻辑像素，而且旧窗口（920x640）小于本应用的最小尺寸。其“高对比度”配色方案会映射为跟随系统
  （开启 Windows 高对比度时使用其颜色）。

## 本预览版尚未包含

- 日志与关于页面、应用图标和打包的可执行文件。
- 在 Windows 缩放 100/125/150/200% 下的显示大小检查（需要手动更改 Windows 缩放）。
- 深色模式下标题栏、滚动条和下拉列表滚动条仍是浅色。
- 不支持自定义配色方案（v0.01.5 的 JSON 主题文件）。

## 兼容性

- `--settings-key <注册表路径>` 将设置指向另一个键（并跳过导入），`--run-key <注册表路径>` 将启动项
  指向另一个 Run 键，用于测试。`--minimized` 仅在托盘中启动。

## 验证

- .NET 解决方案构建：0 个警告，0 个错误。
- .NET 测试：201 个，全部通过（Core 89、App 75、Infrastructure 37）：取值规则、一次性导入（包括
  v0.01.5 写入的 DWORD 缩放值）、窗口位置修正、拖动规则、启动项，以及在 125% 下绘制设置页面的冒烟测试。
- 在使用配置文件副本和临时注册表键运行的应用上，使用真实按键和真实鼠标拖动：每张主题卡片都立即改变
  颜色并保存；跟随系统与 Windows 一致；方向键改变了大小（窗口增大 10%）；拖动滑块时没有任何变化，松开后
  才应用并保存；重置回到 100%；语言切换在两个方向上都改变了侧边栏文字；启动复选框写入并删除了以
  `--minimized` 结尾的带引号命令；关闭到托盘的窗口保存了位置，并在相同位置和大小（3 px 以内）重新打开；
  关闭记忆后已保存的值被删除；保存在远离屏幕之处的位置会完整显示在屏幕内；`--minimized` 使进程保持运行
  而不显示窗口。真实的配置文件、真实的设置键和真实的启动列表均未改变。
