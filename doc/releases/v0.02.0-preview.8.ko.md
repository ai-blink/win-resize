# WindowResizer v0.02.0-preview.8

[English](v0.02.0-preview.8.md) | [한국어](v0.02.0-preview.8.ko.md) | [中文](v0.02.0-preview.8.zh-CN.md) | [日本語](v0.02.0-preview.8.ja.md)

릴리스 날짜: 2026-09-30

새로 작성한 WPF(.NET 10) 데스크톱 앱의 여덟 번째 미리보기입니다. `next/` 아래 소스에서 빌드하며,
배포 실행 파일은 계속 PyQt5 앱 v0.01.5 입니다. 이번에는 오버레이 버튼을 프로필과 분리하고, 4K 화면을
위해 화면 배율 범위를 넓혔습니다.

## 주요 변경

- 오버레이 버튼이 자기 자리를 가집니다. 버튼은 프로필과 따로 자기 이름과 복원할 창 위치·크기(X, Y, 폭,
  높이, 최대화)를 저장합니다. 누르면 직전에 쓰던 창을 그 자리로 옮깁니다. 프로필 매칭, 단축키, 자동
  적용은 관여하지 않습니다.
- 우클릭 메뉴: 버튼 이름(굵게), 저장된 위치, "속성...", "지금 창의 위치로 덮어쓰기", "복제", "이 버튼
  삭제"(먼저 묻습니다).
- 버튼 속성 창(프로필 편집 창과 같은 왼쪽 레일): 일반(이름, 버튼에 보이는 글자), 크기 및 위치(X, Y, 폭,
  높이, 최대화, "직전 창에서 가져오기"), 동작(발동 방식과 머무르는 시간), 외형(모양, 크기, 색).
- 오버레이 페이지에 버튼 목록(속성, 삭제)이 있고, "새 버튼"은 직전에 쓰던 창의 위치와 크기로 버튼을
  만듭니다.
- 처음 실행할 때 오버레이를 켜 두었던 프로필을 버튼으로 한 번 복사합니다(이름, 위치와 크기, 생김새,
  버튼의 화면 자리). 프로필은 바뀌지 않고, 이후에는 다시 복사하지 않아서 지운 버튼이 되살아나지
  않습니다.
- "모두 닫기"가 "모든 버튼 감추기"로 바뀌었습니다. 버튼을 감추기만 하고(감추기 스위치와 같음) 지우지
  않습니다.
- 화면 배율 범위가 75%~250%가 되었습니다(이전 75%~125%). 이 PC에 이미 저장된 값은 바뀌지 않으니
  설정 페이지에서 올려 주세요.

## 이 미리보기에 아직 없는 것

- 화면에서 바로 하는 편집(끌어서 옮기기, 모서리 손잡이로 크기 조절, 편집 모드)은 아직 없습니다. 위치와
  크기는 숫자와 "직전 창에서 가져오기"로 고칩니다.
- "지금 창의 위치로 덮어쓰기"의 되돌리기는 없습니다. 상태 줄에 이전 자리와 새 자리가 나옵니다.
- 프로필 편집 창에 "오버레이 버튼 사용"이 아직 있고 프로필도 오버레이 스타일을 가지고 있습니다. 더 이상
  버튼을 만들지 않으며 안내 문구에 그렇게 적었습니다. 없애는 것은 다음 단계입니다.
- 실행 중인 버튼에 실제 마우스 우클릭을 하는 검증은 하지 못했습니다(아래).
- Windows 배율 100/125/150/200% 확인은 아직 검증하지 않았고, 250%는 눈으로 확인하지 않았습니다.

## 호환성

- 프로필 형식은 바뀌지 않습니다. 오버레이 설정(`HKCU\Software\WindowResizer\Next\Overlay`)에 `buttons`와
  `buttons_migrated` 값이 늘어나며 이전 빌드는 무시합니다. 복사된 버튼의 화면 자리는 옛 프로필 ID 로
  저장돼 있어 그대로 이어집니다.

## 검증

- .NET 솔루션 빌드: 경고 0개, 오류 0개.
- .NET 테스트: 243개, 모두 통과했습니다(Core 105, App 101, Infrastructure 37). 새 테스트는 버튼 모델과
  저장 값, 프로필을 한 번만 복사, 버튼으로 창 옮기기, 창에서 만들기와 덮어쓰기, 이름 중복과 복제, 속성
  뷰모델, 메뉴를 열어 항목을 누르고 속성 창 네 페이지를 그리는 렌더 스모크를 다룹니다.
- 실제 프로필 사본과 임시 레지스트리 키, 일회용 창으로 UI Automation 을 써서 확인했습니다: 오버레이를 켠
  프로필 3개가 버튼 3개가 되었고, "새 버튼"이 일회용 창으로 네 번째 버튼을 만들어 저장했고, 속성 창이 그
  버튼의 이름으로 열렸습니다. 실제 `profiles.json` 과 사본은 바뀌지 않았습니다.
- 검증하지 못한 것: 실행 중인 버튼에 실제 마우스 우클릭. PC 를 쓰는 중이라 커서가 계속 움직였고, 메뉴는
  렌더 스모크로 대신 확인했습니다.
