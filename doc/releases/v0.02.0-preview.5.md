# WindowResizer v0.02.0-preview.5

[English](v0.02.0-preview.5.md) | [한국어](v0.02.0-preview.5.ko.md) | [中文](v0.02.0-preview.5.zh-CN.md) | [日本語](v0.02.0-preview.5.ja.md)

Release date: 2026-09-30

Fifth preview of the rewritten WPF (.NET 10) desktop app. Like the earlier previews
it is built from source under `next/` and is not a packaged release; the
distributed executable is still the PyQt5 app, v0.01.5.

## Highlights

- Log and about page. The top half shows what the app is using right now: version,
  .NET runtime, whether it runs as administrator (windows of an elevated program cannot
  be moved otherwise), the executable, the profiles folder, and the registry keys of the
  settings, overlay and shortcuts. When you test against a copy, this is where you see
  that the real profile folder and the real keys are not touched. Buttons open the profiles
  folder in Explorer, copy all of it (for a bug report) or copy the settings key path.
- The log in the bottom half replaces the PyQt5 debug window. The new app has no logging
  framework, so it records what you could already see: every message that appears in the
  status line, with its time, plus unhandled errors with their full details. Each line is
  info, warning or error (a failed save or apply, no matching window, an unwritable settings
  key are warnings). You can show all lines, warnings and errors, or errors only; keep 100 to
  10000 lines (oldest dropped first); turn auto scroll on or off; clear the log; copy what is
  shown to the clipboard; or export it to a UTF-8 text file with a header. Warning lines are
  bold and coloured, and their text also says WARNING or ERROR, so colour is not the only cue.
- Menu bar: Tools > Log (Ctrl+D) and Help > About open the page, as the menu map promised.
  The English about box of v0.01.5 (with its hard-coded version) is gone.
- A screen exception no longer ends the app. It is recorded as an error in the log and shown
  in the status line, and the app keeps running in the tray. Errors on other threads are
  written to the log before the runtime ends the process.
- Language switches also rebuild the level names and the counts; lines already recorded keep
  the language they were written in.

## Not yet in this preview

- The log lives in memory for the session only; it is not written to a file until you
  export it.
- App icon, a packaged executable, and the Windows 100/125/150/200% scaling smoke.
- Title bar, scroll bars and drop-down scroll bars stay light in dark mode.
- The sidebar shortens the English "Windows and profiles" label.

## Compatibility

- Nothing changes in the profile or settings formats. No new command line options.

## Verification

- .NET solution build: 0 warnings, 0 errors.
- .NET tests: 227 tests, all passed (Core 99, App 91, Infrastructure 37): the log
  (adding, the maximum, trimming, filtering, the export text), the page's view model
  (live rows, filter, clear, copy of only the visible lines, export with BOM, a busy clipboard,
  an unwritable path), status line to log level mapping, the unhandled error entry, the info
  page, and a render smoke of every page with no binding errors.
- On the running app against a copy holding one profile that matches no window, with real
  key presses and the real save dialog: Ctrl+D opened the page and the start-up line was
  there; the info showed this build's version and the copy's folder and temporary registry
  keys, not the real ones; a theme change appeared as an info line; applying the profile
  with no matching window appeared as a warning; the filter reduced the list to the warning,
  then to nothing with the empty message, and back; Copy all put all five lines on the clipboard
  (the clipboard text was saved and restored); Export wrote a UTF-8 file with a BOM, the header
  and the lines through the real Save dialog; Open profiles folder opened Explorer on the copy;
  Clear emptied the list; Help > About opened the page. The real profile file, settings key
  and startup list were unchanged. Handling of unhandled exceptions is covered by a unit
  test, not by crashing the running app.
