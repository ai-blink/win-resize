# WindowResizer v0.02.0-preview.3

[English](v0.02.0-preview.3.md) | [한국어](v0.02.0-preview.3.ko.md) | [中文](v0.02.0-preview.3.zh-CN.md) | [日本語](v0.02.0-preview.3.ja.md)

リリース日: 2026-09-29

新しく書き直した WPF（.NET 10）デスクトップアプリの 3 番目のプレビューです。これまでの
プレビューと同じく `next/` 以下のソースからビルドし、パッケージ配布ではありません。配布される
実行ファイルは引き続き PyQt5 アプリ v0.01.5 です。

## 主な変更

- ショートカットページ。グローバルの「すべて適用」ショートカット 1 つで、全プロファイルを
  一致するすべてのウィンドウに適用します（新しい「プロファイル > すべてのプロファイルを適用」
  メニューと同じ経路）。プロファイルごとにショートカットを最大 3 つ持て、それぞれ動作を選べます:
  プロファイルを適用、ロック解除、常に手前の切り替え、自動適用の切り替え。プロファイルごとの
  スイッチでそのショートカットをまとめてオン/オフします。
- ショートカットは 1 行で選びます: 修飾キーのチップ 4 つ（Ctrl、Alt、Shift、Win）、キー一覧、
  検出ボタン。検出を押してショートカットをそのまま押すと一度に埋まり、手で選ぶこともできます。
  最大 5 キーまで使えます（修飾キー 4 つ + キー 1 つ: Windows は修飾キー以外を 1 つしか受け付け
  ません）。検出中とプロファイル編集ウィンドウが開いている間はグローバル登録を解除するため、
  登録済みのショートカットを押しても動作は実行されず行が埋まります。他のプログラムが既に保持
  している組み合わせは押したキーがそのプログラムに渡るため検出できません。手で選んでください。
  行ごとに保存ボタンがあり、未保存の変更はその旨を表示します。プロファイル編集ウィンドウも同じ行を
  使います。
- 行は変更のたびに即座に検査されます。形式の誤り、他の行との重複、他のプログラムや Windows が
  使っている組み合わせ（例: Win+L）には、理由とともに赤い枠が付きます。そのような組み合わせも
  v0.01.5 と同様に保存され、動作しない理由は警告ボックスで知らせます。
- ページは各ショートカットを登録結果とともに表示します。他のプログラムが使っている組み合わせ、
  形式の誤った組み合わせ、未知の動作、重複は黙って失敗せず理由が表示され、残りは登録されます。
  プロファイルを保存または削除するたびに再登録し、ショートカットに関係しない保存（適用回数など）
  は登録に触れません。
- 「すべて適用」ショートカットは `HKCU\Software\WindowResizer\Next\Hotkeys` に保存します。
  初回に v0.01.5 のファイル `application_hotkeys.json` の値を取り込み（テスト PC では
  Ctrl+Alt+E）、そのファイルには書き込みません。v0.01.5 と同様、Windows が登録を拒否しても
  ショートカットは保存され、ページがそのことを知らせます。
- プロファイルにショートカットのセットがあるとき、プロファイル編集ウィンドウは単一ショートカット
  欄を閉じてショートカットページを案内します。そこで編集しても何も起きない、ということがなくなり
  ます。プロファイル一覧のショートカット列は、登録される最初のショートカットを表示します。

## このプレビューにまだないもの

- 「ロック解除」は解除するものがありません。このプレビューはまだウィンドウをロックしたりマウスを
  閉じ込めたりしないため、ショートカットはステータス行でその旨を知らせるだけです。
- 「自動適用の切り替え」はプロファイルの設定を反転して保存します。新しいウィンドウを検出して自動
  適用する機能はこのプレビューにありません。
- 「常に手前の切り替え」は v0.01.5 と同様、プロファイルではなく最前面のウィンドウに作用します。
- 設定ページ（テーマ、UI スケール、言語）、ログと情報ページ、アプリアイコン、パッケージ化された
  実行ファイル。

## 互換性

- プロファイルは `hotkey_sets` を含め同じ `profiles.json` 形式です。保存時は PyQt5 の編集
  ウィンドウと同様、最初のセットを `hotkey_combination` と `hotkey_action` にも書きます。
  プレビューは渡されたプロファイルフォルダー（`--profiles-dir`）に書き込むため、コピーでテスト
  してください。`--hotkey-key` はテスト用に「すべて適用」ショートカットを別のレジストリキーに
  置きます。

## 検証

- .NET ソリューションのビルド: 警告 0 件、エラー 0 件。
- .NET テスト: 159 件、すべて合格（Core 68、App 61、Infrastructure 30）。登録層に実際の
  キー入力を送るテストを含みます。
- プロファイルのコピーで動作中のアプリに実際のキー入力で: 「すべて適用」ショートカット
  Ctrl+Alt+E が使い捨てウィンドウをプロファイルの位置に移動し、プロファイルのショートカットが
  プロファイルを適用し、常に手前の切り替えが最前面のウィンドウをオン/オフし、自動適用の切り替えが
  設定を両方向に反転して保存しました。他のプログラムが保持する組み合わせは競合の理由とともに一覧に
  表示され、残りは登録されたままでした。登録済みの Ctrl+Alt+E を検出するとウィンドウは動かず行が埋まり、新しい組み合わせを
  検出すると修飾キーとキーが一度に埋まり、チップの切り替えとキーの手動選択もできました。他の
  プログラムが保持する組み合わせは理由とともに行が赤くなり、保存すると値は保存されて警告
  ボックスが出て、空いている組み合わせに変えて保存すると警告なしで新しいショートカットが
  「すべて適用」を実行しました。実際のプロファイルファイルは変わりませんでした。
